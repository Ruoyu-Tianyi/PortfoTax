# PortfoTax · 投后财税雷达

 PE 机构的投后管理，十到三十家被投企业。报表还在靠微信催？口径是否在各说各话？三表断勾稽、账税差异越挂越大，要等到季报甚至审计，风险才浮出水面——那时，滞纳金和信用降级已成事实。**ProtfoTax**—基于PE/VC 投后被投企业财税一致性与申报监测的工具（MVP 原型）,用六条财税一致性规则自动校验被投企业数据，用申报日历盯住每一个截止日，让风险从'事后发现'变成'当月看见'。

## 快速开始

```bash
# 直接双击打开即可运行（零构建）
app/index.html
```

或者起本地服务（可选）：

```bash
cd app
python -m http.server 8080
# 浏览器访问 http://localhost:8080
```

## 核心功能

| 模块 | 说明 |
|------|------|
| 📊 组合总览 | 企业卡片墙、组合健康分、风险分布图、待申报提醒 |

## 页面与路由

| 路由            | 页面         | 内容                                                         |
| --------------- | ------------ | ------------------------------------------------------------ |
| `#/dashboard`   | 组合总览     | 组合级 KPI（平均健康分 / 红色预警数 / 本月待申报数 / 规则命中数）、企业卡片墙、健康分排行、风险分布 |
| `#/company/:id` | 企业详情     | 三表及申报关键数据、R1–R6 校验结果（命中状态 / 差异金额 / 差异率 / 严重度）、模板化 AI 风险解读与处置建议、本期申报状态 |
| `#/calendar`    | 申报监测日历 | 风险提醒列表（逾期按天数排序，附滞纳金估算 万分之五/日）、6 月申报日历网格、状态统计 |
| `#/report/:id`  | 企业体检报告 | 单企业月度财税体检报告，点「打印 / 导出 PDF」即可经浏览器打印为 PDF |

页面间连通：Dashboard 卡片 → 企业详情 → 体检报告；报告页与日历页均可回跳。

## 规则引擎（js/rules.js）

纯函数设计，`Rules.evaluateCompany(company, baseDate)` 输入企业数据、输出完整评估结果，不依赖 DOM，可直接在 Node 中单测：

```bash
node -e "global.window={};require('./data/demo.js');require('./js/rules.js');\
console.log(window.Rules.evaluateCompany(window.DEMO.companies[4],'2026-06-20'))"
```

| 规则 | 名称          | 判定                             | 阈值         |
| ---- | ------------- | -------------------------------- | ------------ |
| R1   | 三表勾稽      | 净利润 ≈ 未分配利润变动 + 分红   | 差异率 > 3%  |
| R2   | 账税一致性    | 账面营业收入 vs 增值税申报销售额 | 差异率 > 5%  |
| R3   | 所得税匹配    | 利润总额 vs 企税应纳税所得额     | 差异率 > 10% |
| R4   | 发票-申报比对 | 开票金额 vs 增值税申报收入       | 差异率 > 5%  |
| R5   | 现金流勾稽    | 收现比 = 销售收现 / 营业收入     | 超出 0.7–1.3 |
| R6   | 社保个税匹配  | 工资总额 vs 社保/个税申报基数    | 差异率 > 10% |

严重度分档（高/中/低）按差异率划分；健康分 = 100 − 规则扣分（高 30 / 中 20 / 低 10）− 申报扣分（逾期 12 / 临期 4），等级：绿 ≥ 90，黄 60–89，红 < 60。

滞纳金估算：税额 × 0.05% × 逾期天数（《税收征管法》第三十二条口径，仅供演示）。

## 后续接入真实数据源

1. **API 接入**：将 `data/demo.js` 替换为后端接口返回的同构 JSON（企业元信息 + `finance` 三表科目 + `filings` 申报记录）。规则引擎 `rules.js` 无需改动——只要保证字段口径一致即可复用。
2. **Excel 导入**：在前端引入 SheetJS（xlsx），把被投企业月度填报模板解析为 `finance` / `filings` 结构后喂给规则引擎。
3. **真实 AI 解读**：`rules.js` 中的 `AI_TEMPLATES` 目前为模板化模拟输出；正式环境可将规则命中结果（规则编号、差异金额、差异率、科目明细）作为 prompt 上下文调用大模型接口生成解读与建议。
4. **数据基准日**：当前 `meta.baseDate` 为固定演示日期；接入真实数据后应改为动态当日，申报状态机（已申报/临期/逾期）会自动按当日重新计算。
